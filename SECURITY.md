# Security

Prometheus–Momus orchestrates autonomous model sessions. Treat it like any
other automation capable of inspecting a project and invoking external model
services.

## Recommended default

Use:

```ini
sandbox = read-only
```

for brainstorming, research, review, and design.

## Write-capable modes

`workspace-write` or less restrictive modes increase risk.

Only enable them when:

- the task actually requires file modification;
- the target project is backed up/version controlled;
- you understand the Codex sandbox and approval behavior in your environment.

## Prompt injection

Repository files, web pages, external documents, and other tool outputs may
contain instructions intended to influence an agent.

The two-agent setup is not a security boundary against prompt injection.

## Blindness

Momus's pre-analysis is operationally isolated from Prometheus's opening
response by keeping live debate artifacts outside the project workspace.

This is not cryptographic isolation. Codex maintains its own user-level
session state, and a sufficiently adversarial agent with broad filesystem
access could potentially seek orchestration metadata. The Momus role prompt
explicitly forbids doing so.

## Secrets

Do not put passwords, API keys, private credentials, or other secrets in:

- `task.md`;
- role files;
- project files the agents do not need;
- prompts intended for publication.

Run archives may contain substantial excerpts of model reasoning outputs,
project observations, source names, and web findings. Review them before
publishing.

## Consensus is not truth

Two agents can share the same blind spots.

For high-stakes scientific, legal, financial, safety, security, or production
decisions, independent human review and empirical validation remain necessary.

Patent or prior-art discussion generated by the agents is not legal advice.
